Estas dos líneas resuelven un problema práctico: ¿dónde guardar los archivos generados, sin importar desde qué directorio se ejecute el script?

  • __file__ es una variable especial de Python que contiene la ruta del archivo que se está ejecutando.
  • os.path.abspath() convierte esa ruta en una ruta absoluta (desde la raíz del sistema de archivos).
  • os.path.dirname() extrae solo el directorio que contiene el script.
  • os.path.join(..., "resultados") construye la ruta completa a la carpeta resultados/ dentro de ese directorio, usando el separador correcto para el sistema operativo (/ en Linux/Mac, \ en Windows).
  • os.makedirs(..., exist_ok=True) crea esa carpeta si no existe. El parámetro exist_ok=True evita que el programa falle si la carpeta ya existe.
🔑 Por qué esto importa
Sin este bloque, si alguien ejecutara el script desde otra carpeta, los archivos PNG y GIF se guardarían en un lugar inesperado. Esta construcción es una práctica recomendada en scripts científicos para garantizar que los resultados siempre aparezcan junto al código fuente.

Las Ecuaciones Diferenciales del Sistema de Lorenz

Antes de leer el código, necesitás entender qué sistema matemático estamos integrando. En 1963, el meteorólogo Edward Lorenz derivó el siguiente sistema de tres ecuaciones diferenciales ordinarias (EDOs) como modelo simplificado de convección atmosférica:

$$\frac{dx}{dt} = \sigma(y - x)$$ $$\frac{dy}{dt} = x(\rho - z) - y$$ $$\frac{dz}{dt} = xy - \beta z$$

El estado del sistema en cada instante es el vector $(x, y, z)$. Las derivadas temporales nos dicen cómo cambia ese vector. El sistema es determinista (no hay aleatoriedad), continuo (el tiempo es una variable real), y autónomo (las ecuaciones no dependen explícitamente de $t$).

Significado físico de las variables

VariableSignificado físico originalInterpretación dinámica
$x$Intensidad de la corriente de convección (velocidad del fluido)Coordenada que oscila entre lóbulos del atractor
$y$Diferencia de temperatura entre la corriente ascendente y descendenteDesfasaje térmico horizontal
$z$Distorsión del perfil de temperatura respecto al equilibrio linealSiempre positivo, oscila entre ~0 y ~50 con ρ=28

Significado de los parámetros

ParámetroNombreValor estándarSignificado
$\sigma$ (sigma) Número de Prandtl 10.0 Razón entre la difusividad cinemática del fluido y la difusividad térmica. Controla qué tan rápido responde $x$ a las diferencias en $y$.
$\rho$ (rho) Número de Rayleigh reducido 28.0 Razón entre el número de Rayleigh y el número de Rayleigh crítico. Es el parámetro de control: al variarlo, el sistema transita entre distintos regímenes dinámicos. Es el parámetro más importante del sistema.
$\beta$ (beta) Factor geométrico 8/3 ≈ 2.667 Depende de la geometría de la celda de convección. Controla la velocidad de disipación de $z$.
🌪️ ¿Por qué el sistema es caótico?

Observá el término $x(\rho - z)$ en la segunda ecuación y $xy$ en la tercera. Estos productos entre variables crean no linealidades: el comportamiento del sistema no es simplemente la suma de los comportamientos de cada variable por separado. Las no linealidades son la fuente del caos. Un sistema puramente lineal (sin esos productos) nunca podría ser caótico.

La función lorenz(t, estado, sigma, rho, beta)

Python · Líneas 35–40
def lorenz(t, estado, sigma=10.0, rho=28.0, beta=8.0/3.0):
    x, y, z = estado
    dx_dt = sigma * (y - x)
    dy_dt = x * (rho - z) - y
    dz_dt = x * y - beta * z
    return [dx_dt, dy_dt, dz_dt]

Esta función implementa directamente las tres ecuaciones de Lorenz. Es el corazón matemático de todo el programa.

  • Qué recibe: el tiempo actual t (que el sistema no usa explícitamente, pero que solve_ivp debe pasar por convención), el vector estado = [x, y, z] en ese instante, y los tres parámetros.
  • Qué hace: desempaqueta el estado, calcula las tres derivadas según las ecuaciones de Lorenz, y las devuelve como lista.
  • Qué devuelve: la lista [dx/dt, dy/dt, dz/dt], que es la velocidad del estado en ese instante. Matemáticamente, es el campo vectorial evaluado en el punto (x,y,z).
📌 ¿Por qué aparece t si no se usa?
Es una convención de la API de solve_ivp. El integrador necesita poder llamar a la función de esta forma: lorenz(t, y, ...). Para sistemas autónomos (donde las ecuaciones no dependen explícitamente del tiempo), t simplemente no se usa dentro del cuerpo de la función, pero igual debe estar en la firma.

La función simular()

Python · Líneas 42–45
def simular(estado_0, t_span, t_eval, sigma=10.0, rho=28.0, beta=8.0/3.0):
    """Integra el sistema con Runge-Kutta 4(5) adaptativo."""
    return solve_ivp(lorenz, t_span, estado_0, t_eval=t_eval,
                     args=(sigma, rho, beta), method="RK45", rtol=1e-8, atol=1e-8)

Esta función es un wrapper conveniente alrededor de solve_ivp. Encapsula todos los parámetros de integración comunes para no repetirlos en cada bloque del programa.

Parámetros de simular()

estado_0

Lista con las condiciones iniciales $[x_0, y_0, z_0]$. Define el punto de partida de la trayectoria en el espacio de fases.

t_span

Tupla (t_inicio, t_fin) que define el intervalo total de integración.

t_eval

Array de tiempos en los que se quiere obtener la solución. No son los pasos del integrador, sino los puntos de salida.

args=(sigma, rho, beta)

Parámetros extra que se pasan a la función lorenz(). Permite cambiar el comportamiento sin modificar la función.

El método RK45 y solve_ivp en profundidad

solve_ivp ("solve initial value problem") es la función de SciPy para integrar sistemas de EDOs con condición inicial dada. Con method="RK45", usa el método de Runge-Kutta de orden 4(5) de Dormand-Prince.

¿Qué es Runge-Kutta 4(5)?

La idea central de cualquier método de Runge-Kutta es avanzar la solución de $t$ a $t + h$ evaluando el campo vectorial en varios puntos intermedios y combinando esas evaluaciones para obtener una estimación precisa del siguiente estado. El método RK45 usa 6 evaluaciones por paso:

$$k_1 = f(t_n,\, y_n)$$ $$k_2 = f\!\left(t_n + \tfrac{h}{5},\; y_n + \tfrac{h}{5}k_1\right)$$ $$\vdots$$ $$y_{n+1}^{(4)} = y_n + h\sum_{i=1}^{6} b_i k_i \quad \text{(orden 4)}$$ $$y_{n+1}^{(5)} = y_n + h\sum_{i=1}^{6} b_i^* k_i \quad \text{(orden 5)}$$

El "truco" del RK45 es que calcula simultáneamente una solución de orden 4 y una de orden 5 usando las mismas evaluaciones de $f$. La diferencia entre ambas estima el error cometido en el paso.

Control adaptativo del paso

Si el error estimado es mayor que la tolerancia especificada, el integrador reduce $h$ y repite el paso. Si el error es mucho menor, aumenta $h$ para acelerar la integración. Esto es el control adaptativo del paso: el integrador elige automáticamente pasos pequeños donde la solución varía rápido (en las oscilaciones) y pasos grandes donde varía lento.

📐 Tolerancias rtol y atol

El control del error usa una combinación de dos tolerancias:

  • rtol=1e-8 (tolerancia relativa): el error en cada componente del estado debe ser menor que rtol * |y_i|. Es decir, el error relativo no supera $10^{-8}$.
  • atol=1e-8 (tolerancia absoluta): establece un piso para el error admisible cuando la solución es muy pequeña (cerca de cero). Evita que el integrador exija precisión imposible cuando $|y_i| \approx 0$.

El criterio combinado es: error $\leq$ atol + rtol × |y|. El valor $10^{-8}$ es estricto y adecuado para cálculos de Lyapunov donde se mide separaciones de $10^{-8}$.

📌 Diferencia entre pasos internos y t_eval

Hay que distinguir dos cosas distintas:

  • Pasos internos del integrador: los tamaños de paso $h$ que RK45 elige automáticamente para controlar el error. Pueden ser irregulares y muy numerosos. No los vemos directamente.
  • t_eval: los instantes de tiempo en que queremos que la solución nos informe el resultado. Estos son los que fijamos nosotros con np.linspace(). SciPy interpola internamente para dar el valor exacto en esos tiempos.

En otras palabras: el integrador trabaja con sus propios pasos variables internamente, y al llegar a cada tiempo pedido en t_eval nos reporta el estado del sistema.

El objeto solución que devuelve solve_ivp

solve_ivp devuelve un objeto con varios atributos. En este programa se usan:

sol.t

Array 1D con los tiempos evaluados (coincide con t_eval). Forma: (N,).

sol.y

Matriz 2D con la solución. Forma: (3, N). Fila 0 = x(t), fila 1 = y(t), fila 2 = z(t).

sol.status

Código de estado: 0 = éxito, 1 = se alcanzó el intervalo máximo, -1 = error.

sol.y[:, -1]

El estado final (última columna). Forma: (3,). Se usa para encadenar integraciones.

Gráficos individuales: el patrón "lista de tuplas"

La variable series es una lista de tuplas, donde cada tupla agrupa todo lo necesario para generar un gráfico: título, datos, color y nombre de archivo. El for que sigue itera sobre esa lista y genera los tres gráficos con exactamente el mismo código, cambiando solo los valores de cada tupla.

Este patrón es muy elegante: en lugar de repetir el mismo bloque de código tres veces con pequeñas variaciones, se factoriza en una sola función y se le pasan los datos variables. Si en el futuro se quisiera cambiar el estilo de todos los gráficos, habría que modificar una sola línea.

  • plt.subplots(figsize=(10, 4)): crea una figura de 10 pulgadas de ancho y 4 de alto, y devuelve la figura y el eje de coordenadas.
  • ax.plot(t, datos, ...): dibuja la curva $\text{datos}(t)$.
  • ax.set(...): forma compacta de llamar a ax.set_title(), ax.set_xlabel(), etc., todo a la vez.
  • plt.tight_layout(): ajusta automáticamente los márgenes para evitar que etiquetas y títulos se superpongan.
  • plt.savefig(..., dpi=200): guarda la figura como PNG con resolución de 200 puntos por pulgada (suficiente para presentaciones).

Gráfico conjunto: sharex=True

plt.subplots(3, 1, sharex=True) crea tres paneles apilados verticalmente que comparten el eje x. Esto significa que si el usuario hace zoom en el tiempo en un panel, los tres se mueven al unísono. Es una elección de diseño muy útil para comparar la evolución simultánea de x, y, z.

🔎 ¿Qué se ve en estos gráficos?

Al graficar x(t), y(t), z(t) verás que las tres variables oscilan de manera compleja y aperiódica. Nunca repiten exactamente el mismo patrón. Esto es el caos en el tiempo: la solución es perfectamente determinista (siempre la misma si usamos las mismas condiciones iniciales), pero no es periódica. z(t) siempre es positiva (oscila alrededor de ~25); x(t) e y(t) cambian de signo, saltando erráticamente de un "lóbulo" al otro del atractor.

def bloque_2_atractor_3d(t, x, y, z, t_corte=5.0):

               label=r"Puntos fijos $C^+, C^-$", zorder=5)

    ax.set(title=r"Atractor Extraño de Lorenz ($\sigma=10, \rho=28, \beta=8/3$)",
           xlabel="x [u.a.]", ylabel="y [u.a.]", zlabel="z [u.a.]")
    ax.view_init(elev=22, azim=-62)
    ax.legend(loc="upper left")

El transitorio y la máscara booleana

La línea mask = t >= t_corte crea un array booleano: cada elemento es True si el tiempo correspondiente es mayor o igual a 5 y False en caso contrario. Después, x[mask] selecciona solo los valores de x donde mask es True.

¿Por qué descartar el transitorio? Al comienzo de la integración, la trayectoria parte desde el punto $(1, 1, 1)$, que probablemente está fuera del atractor. Durante los primeros instantes, la solución "cae" hacia el atractor pero aún no está en él. Esta fase inicial se llama transitorio. Al descartarla, el gráfico muestra únicamente la dinámica asintótica del sistema: la forma del atractor sin la "cola" inicial que distorsionaría la visualización.

📌 ¿Qué es el espacio de fases?

El espacio de fases (o espacio de estados) es el espacio matemático cuyas coordenadas son las variables del sistema: en este caso $(x, y, z)$. Cada punto del espacio de fases representa un estado completo del sistema. La solución del sistema traza una curva continua en este espacio, llamada trayectoria u órbita. El gráfico 3D de este bloque muestra esa trayectoria.

Los puntos de equilibrio $C^+$ y $C^-$

Un punto de equilibrio (o punto fijo) es un estado $(x^*, y^*, z^*)$ donde todas las derivadas son cero, es decir, el sistema no evoluciona. Para el sistema de Lorenz con $\rho > 1$, hay tres puntos de equilibrio:

$$C^0 = (0,\, 0,\, 0)$$ $$C^{\pm} = \left(\pm\sqrt{\beta(\rho-1)},\;\pm\sqrt{\beta(\rho-1)},\;\rho-1\right)$$

El código calcula $C^+$ y $C^-$ para los valores estándar ($\beta = 8/3$, $\rho = 28$):

Cálculo de los puntos fijos
xc = np.sqrt((8/3) * (28.0 - 1.0))   # = sqrt(8/3 × 27) = sqrt(72) ≈ 8.485
zc = 28.0 - 1.0                        # = 27.0

# C+ = (8.485, 8.485, 27.0)
# C- = (-8.485, -8.485, 27.0)
🔬 Interpretación física y matemática de C⁺ y C⁻

Aunque el sistema con $\rho = 28$ tiene esos puntos de equilibrio, son inestables. Si pusieras el sistema exactamente en $C^+$, teóricamente se quedaría ahí; pero cualquier perturbación infinitesimalmente pequeña lo alejaría exponencialmente. En el gráfico 3D, el atractor "rodea" a $C^+$ y $C^-$: la trayectoria orbita alrededor de uno de ellos por un número aleatorio de vueltas, luego salta al otro, y así indefinidamente. Los puntos rojos en el gráfico son precisamente $C^+$ y $C^-$.

El gráfico 3D en Matplotlib

La línea ax = fig.add_subplot(projection="3d") crea un eje tridimensional. A diferencia de un eje 2D, este tiene tres ejes coordenados. La línea ax.view_init(elev=22, azim=-62) establece el punto de vista de la cámara virtual: elevación de 22 grados sobre el plano horizontal, y azimut de −62 grados. Esta perspectiva particular muestra bien la forma de mariposa del atractor.

¿Por qué dos condiciones iniciales casi idénticas?

La diferencia entre los dos estados iniciales es:

$$\Delta x_0 = 10^{-8}, \quad \Delta y_0 = 0, \quad \Delta z_0 = 0$$

Un centímetro equivale a $10^{-2}$ metros; $10^{-8}$ metros es la escala de los nanómetros. Esta perturbación es astronómicamente pequeña. En un sistema físico real, sería imposible de distinguir experimentalmente.

El propósito es demostrar que el sistema de Lorenz es sensitivamente dependiente de las condiciones iniciales: una diferencia inicial que parece despreciable crece hasta hacerse macroscópica en tiempo finito. Esta propiedad es la esencia del caos determinista.

La distancia euclídea: np.linalg.norm()

La distancia entre dos puntos del espacio de fases $\mathbf{X}_1(t) = (x_1, y_1, z_1)$ y $\mathbf{X}_2(t) = (x_2, y_2, z_2)$ es:

$$d(t) = \|\mathbf{X}_1(t) - \mathbf{X}_2(t)\| = \sqrt{(x_1-x_2)^2 + (y_1-y_2)^2 + (z_1-z_2)^2}$$

En el código: s1.y - s2.y calcula la diferencia entre las dos matrices de solución (cada columna es un instante de tiempo); y np.linalg.norm(..., axis=0) calcula la norma euclídea de cada columna por separado (a lo largo del eje 0, que corresponde a las tres componentes espaciales). El resultado es un array 1D de $N$ elementos, donde cada elemento es $d(t_k)$.

La escala logarítmica: ax.semilogy()

ax.semilogy() grafica con el eje y en escala logarítmica y el eje x en escala lineal. ¿Por qué usar escala logarítmica?

En un sistema caótico, la separación entre dos trayectorias cercanas crece inicialmente de manera exponencial:

$$d(t) \approx d_0 \, e^{\lambda_{\max} t}$$

Si graficamos $d(t)$ en escala lineal, veríamos una curva que se dispara hacia arriba de forma casi vertical. En cambio, si tomamos el logaritmo:

$$\ln d(t) \approx \ln d_0 + \lambda_{\max} t$$

Esto es una línea recta en el gráfico semilogarítmico, con pendiente $\lambda_{\max}$. El crecimiento exponencial se vuelve visible como una rampa lineal, lo cual es mucho más fácil de analizar. Cuando la distancia se satura (porque las trayectorias quedan confinadas dentro del atractor), la curva se aplana.

🌪️ El caos determinista explicado con este gráfico

Lo que el gráfico de $d(t)$ en escala log te muestra es: hay una fase inicial donde las dos trayectorias son casi indistinguibles (la curva está cerca de $10^{-8}$), luego una fase de crecimiento exponencial (la recta ascendente en el gráfico log), y finalmente una saturación cuando las trayectorias se encuentran en partes completamente distintas del atractor y la distancia no puede crecer más. Este es el límite de predictibilidad del sistema.

Máximo Exponente de Lyapunov (Método de Benettin)

def bloque_4_lyapunov(d0=1e-8, tau=0.1, n_pasos=250):
    """
    Algoritmo de Benettin (1976):
    Evoluciona 2 estados a distancia d0. Tras cada intervalo tau,
    mide la separación d1, acumula ln(d1/d0) y renormaliza a distancia d0.
    """
    # 1. Pre-evolución para entrar en el atractor
    s_ref = solve_ivp(lorenz, (0.0, 10.0), [1.0, 1.0, 1.0],
                      method="RK45", rtol=1e-8, atol=1e-8).y[:, -1]
    s_pert = s_ref.copy(); s_pert[0] += d0

    suma_log = 0.0
    tiempos, lyap_acumulado = [], []

    for k in range(1, n_pasos + 1):
        # Avanzar ambas trayectorias un paso tau
        s_r_fin = solve_ivp(lorenz, (0.0, tau), s_ref, method="RK45", rtol=1e-8, atol=1e-8).y[:, -1]
        s_p_fin = solve_ivp(lorenz, (0.0, tau), s_pert, method="RK45", rtol=1e-8, atol=1e-8).y[:, -1]

        # Medir separación y acumular tasa logarítmica
        delta = s_p_fin - s_r_fin
        d1 = np.linalg.norm(delta)
        suma_log += np.log(d1 / d0)

        t_actual = k * tau
        tiempos.append(t_actual)
        lyap_acumulado.append(suma_log / t_actual)

        # Renormalización: reubicar s_pert a distancia d0 en la dirección de divergencia
        s_ref = s_r_fin
        s_pert = s_r_fin + d0 * (delta / d1)

    lambda_est = lyap_acumulado[-1]
    return lambda_est

¿Qué mide el exponente máximo de Lyapunov?

El exponente máximo de Lyapunov $\lambda_{\max}$ cuantifica la tasa promedio de divergencia exponencial entre trayectorias inicialmente cercanas. Matemáticamente:

$$\lambda_{\max} = \lim_{t \to \infty} \lim_{\|\delta_0\| \to 0} \frac{1}{t} \ln \frac{\|\delta(t)\|}{\|\delta_0\|}$$

Donde $\delta_0$ es la separación inicial y $\delta(t)$ es la separación en el tiempo $t$. Si $\lambda_{\max} > 0$, el sistema es caótico: pequeñas diferencias crecen exponencialmente. Si $\lambda_{\max} \leq 0$, el sistema es regular (puntos fijos, ciclos límite).

El método de Benettin paso a paso

El problema práctico con la definición anterior es que si las trayectorias divergen exponencialmente, en tiempo finito la separación $\|\delta(t)\|$ se hace tan grande que las dos trayectorias ya no están "cerca" en el sentido que requiere la teoría. Benettin (1976) propuso un algoritmo que resuelve esto:

Paso 0: Pre-evolución

Se integra el sistema 10 unidades de tiempo para asegurarse de que el punto de referencia esté en el atractor antes de comenzar el cálculo. Si se empezara desde $(1,1,1)$ directamente, los primeros pasos del algoritmo medirían la dinámica transitoria, que no es representativa del atractor.

Paso 1: Avanzar ambas trayectorias

Se toman los dos estados (referencia y perturbado) y se integran cada uno durante tau = 0.1 unidades de tiempo. solve_ivp(...).y[:, -1] extrae solo el estado final (última columna de la matriz de solución).

Paso 2: Medir la separación

delta = s_p_fin - s_r_fin es el vector diferencia entre los dos estados finales. d1 = np.linalg.norm(delta) es su norma: la distancia euclídea. Luego se acumula:

$$\text{suma\_log} \mathrel{+}= \ln\!\left(\frac{d_1}{d_0}\right)$$

La renormalización: el corazón del algoritmo

La línea más importante
s_pert = s_r_fin + d0 * (delta / d1)

Analicemos esta línea cuidadosamente:

  • delta / d1 es el vector unitario en la dirección de divergencia (tiene norma 1).
  • d0 * (delta / d1) es un vector de norma d0 en esa misma dirección.
  • s_r_fin + ... ubica el nuevo punto perturbado a una distancia exactamente d0 del punto de referencia, en la dirección en que las trayectorias divergieron.

El propósito es doble. Primero, se evita que la separación crezca tanto que las dos trayectorias estén en regiones completamente distintas del atractor. Segundo, se sigue midiendo la divergencia en la dirección más inestable, que es precisamente la dirección que determina $\lambda_{\max}$.

Estimación acumulada

En cada paso $k$, se guarda la estimación temporal:

$$\hat{\lambda}(k\tau) = \frac{1}{k\tau}\sum_{i=1}^{k}\ln\!\left(\frac{d_1^{(i)}}{d_0}\right)$$

Esto es la media temporal de los logaritmos de las tasas de estiramiento. Si el exponente converge, esta cantidad se estabiliza cerca de $\lambda_{\max} \approx 0.906$.

Interpretación física de λ > 0

Un exponente de Lyapunov positivo $\lambda \approx 0.906$ significa que dos estados que difieren en $10^{-8}$ se separarán hasta ser comparables con el tamaño del atractor en un tiempo del orden de:

$$T_{\text{predicción}} \approx \frac{\ln(d_{\text{atractor}} / d_0)}{\lambda_{\max}} \approx \frac{\ln(100 / 10^{-8})}{0.906} \approx \frac{23}{0.906} \approx 25 \text{ u.a.}$$

Más allá de ese horizonte temporal, toda predicción determinista se vuelve inútil. No importa cuán precisa sea la medición inicial: el horizonte de predictibilidad es finito y está determinado por $\lambda_{\max}$.

Para cada valor de ρ en rhos_barrido, el código ejecuta una versión reducida del algoritmo de Benettin: 100 pasos (en lugar de 250) y tolerancia por defecto (en lugar de 1e-8). El resultado es una estimación aproximada de $\lambda_{\max}(\rho)$.

Para un análisis cuantitativo preciso, se deberían aumentar los pasos y las tolerancias.

La bifurcación de Hopf subcrítica

La línea vertical en $\rho_H \approx 24.74$ marca la bifurcación de Hopf subcrítica. En este valor de ρ ocurre una transición cualitativamente importante en el sistema.

Para $\rho < 1$: el origen $(0,0,0)$ es el único atractor estable.

Para $1 < \rho < \rho_H$: existen los dos puntos fijos estables $C^+$ y $C^-$.

Para $\rho \gtrsim \rho_H$: los puntos fijos pierden su estabilidad en una bifurcación de Hopf. En lugar de converger suavemente a $C^+$ o $C^-$, el sistema empieza a orbitar a su alrededor. Para $\rho = 28$, esto resulta en el caos observado.

🔬 ¿Qué es exactamente una bifurcación de Hopf?

Una bifurcación de Hopf ocurre cuando un punto fijo pierde su estabilidad porque dos autovalores complejos conjugados del jacobiano del sistema cruzan el eje imaginario (la parte real pasa de negativa a positiva). En ese momento, el punto fijo deja de ser un atractor estable y aparece una solución oscilatoria (ciclo límite). En el caso de Lorenz, la bifurcación es subcrítica, lo que significa que el ciclo límite que emerge es inestable. Esto es lo que lleva al comportamiento caótico en lugar de oscilaciones simples.

def bloque_6_seccion_poincare(z_corte=27.0):
    sol = simular([1.0, 1.0, 1.0], (0.0, 120.0), np.linspace(10.0, 120.0, 15000))
    x, y, z = sol.y
    cruces_x, cruces_y = [], []

    # Detectar cruces de z_corte de abajo hacia arriba con interpolación lineal
    for k in range(len(z) - 1):
        if z[k] < z_corte and z[k + 1] >= z_corte:
            frac = (z_corte - z[k]) / (z[k + 1] - z[k])
            xi = x[k] + frac * (x[k + 1] - x[k])
            yi = y[k] + frac * (y[k + 1] - y[k])
            # dz/dt = x*y - beta*z > 0
            if (xi * yi - (8.0 / 3.0) * z_corte) > 0:
                cruces_x.append(xi)
                cruces_y.append(yi)

    ax.scatter(cruces_x, cruces_y, ...)
    return len(cruces_x)

¿Qué es una sección de Poincaré?

Una sección de Poincaré es una técnica para estudiar un sistema continuo en tres dimensiones "fotografiando" solo los instantes en que la trayectoria atraviesa un plano elegido. En lugar de ver la curva continua en el espacio 3D, vemos solo los puntos de intersección con ese plano.

Esta reducción de 3D → 2D es muy poderosa: si el sistema fuera periódico simple, veríamos un número fijo de puntos (uno por período). Si fuera cuasiperiódico, veríamos una curva cerrada. Si es caótico, veremos una nube de puntos con estructura fractal.

¿Por qué z = 27?

El valor $z = 27$ es una elección informada: es aproximadamente el valor de $z$ en los puntos fijos $C^+$ y $C^-$ (que están en $z^* = \rho - 1 = 27$). Esto significa que el plano $z = 27$ pasa justo por las "cinturas" de las dos espirales del atractor, donde la trayectoria las cruza regularmente. Un plano mal elegido podría cortar muy pocas veces o dar una geometría difícil de interpretar.

Detección de cruces: el bucle

El bucle for k in range(len(z) - 1) recorre todos los pares consecutivos de puntos de la trayectoria. Para cada par $(k, k+1)$, verifica si el plano $z = 27$ está entre ellos:

Condición de cruce
if z[k] < z_corte and z[k + 1] >= z_corte:  # Cruce ascendente

Esto detecta cuando la trayectoria pasa de estar debajo del plano ($z_k < 27$) a estar arriba o exactamente en él ($z_{k+1} \geq 27$).

Interpolación lineal

Los puntos de la solución numérica no caen exactamente en $z = 27$; solo sabemos que el cruce ocurre entre los instantes $k$ y $k+1$. Para obtener las coordenadas $x$ e $y$ en el momento exacto del cruce, se usa interpolación lineal:

$$f = \frac{z_{\text{corte}} - z_k}{z_{k+1} - z_k}, \quad x_i = x_k + f\,(x_{k+1} - x_k), \quad y_i = y_k + f\,(y_{k+1} - y_k)$$

El parámetro $f$ (llamado frac en el código) vale 0 si el cruce ocurre exactamente en $k$, y 1 si ocurre exactamente en $k+1$. Para cualquier valor intermedio, la interpolación da la posición estimada en el momento del cruce.

La condición dz/dt > 0

Verificación de la dirección del cruce
if (xi * yi - (8.0 / 3.0) * z_corte) > 0:

Esta condición evalúa directamente la ecuación del sistema: $\dot{z} = xy - \beta z$. En el punto interpolado $(x_i, y_i, z_{\text{corte}})$:

$$\dot{z} = x_i y_i - \frac{8}{3} \cdot 27 > 0$$

¿Por qué exigir $\dot{z} > 0$? Porque queremos contar solo los cruces ascendentes (la trayectoria pasa el plano de abajo hacia arriba). En un sistema 3D, la trayectoria puede cruzar el mismo plano en ambas direcciones. Si contáramos ambas direcciones, obtendríamos una sección con estructura diferente. La elección de solo cruces ascendentes es una convención que garantiza que siempre contamos los mismos tipos de eventos dinámicos.

🔎 ¿Por qué la condición de arriba ya no es suficiente?

La condición z[k] < z_corte and z[k+1] >= z_corte garantiza que el punto va de abajo hacia arriba entre los dos instantes discretos. Pero con una alta densidad de puntos, puede haber casos donde la trayectoria toca el plano tangencialmente (sube, llega a z=27, y baja sin llegar a cruzarlo de verdad). La verificación adicional de $\dot{z} > 0$ descarta esos casos, usando la información exacta de la ecuación diferencial.

¿Qué es un diagrama de bifurcaciones?

Un diagrama de bifurcaciones muestra cómo cambia la estructura de la solución asintótica de un sistema dinámico al variar un parámetro de control. En este caso, el eje x es $\rho$ y el eje y son los valores que alcanzan los máximos locales de $z(t)$ en el régimen estacionario.

Detección de máximos locales: indexado de arrays

La línea clave
picos = z[1:-1][(z[1:-1] > z[:-2]) & (z[1:-1] > z[2:])]

Esta línea parece compleja, pero su lógica es clara. Un máximo local en el índice $k$ satisface: $z_{k-1} < z_k$ y $z_k > z_{k+1}$.

En NumPy, se puede expresar esto de forma vectorial:

  • z[1:-1]: todos los elementos excepto el primero y el último (los candidatos a ser picos).
  • z[:-2]: todos los elementos excepto los dos últimos (los vecinos de la izquierda).
  • z[2:]: todos los elementos excepto los dos primeros (los vecinos de la derecha).
  • (z[1:-1] > z[:-2]): array booleano que es True donde el elemento es mayor que su vecino izquierdo.
  • &: operador AND elemento a elemento entre dos arrays booleanos.
  • El resultado final: z[1:-1][mask_picos] selecciona solo los valores donde ambas condiciones son verdaderas.
📌 Por qué se usan máximos de z y no de x o y

La variable $z$ es siempre positiva y sus máximos locales ocurren cuando la trayectoria llega a la parte superior de cada "lóbulo" del atractor. Esta es una elección canónica en la literatura de caos: los máximos de $z$ son indicadores robustos del comportamiento dinámico del sistema. Además, la cantidad de máximos distintos está directamente relacionada con la complejidad del atractor.

Cuántos puntos de la trayectoria se revelan en cada cuadro. Con ~1000 puntos y 100 cuadros: paso ≈ 10.

Paso 4: La función actualizar(frame) explicada en detalle

La función de actualización cuadro a cuadro
def actualizar(frame):
    fin = min(len(xs), (frame + 1) * paso)      # ¿Hasta qué punto mostramos?
    linea.set_data(xs[:fin], ys[:fin])              # Actualizar x e y de la trayectoria
    linea.set_3d_properties(zs[:fin])               # Actualizar z de la trayectoria
    if fin > 0:
        cabeza.set_data([xs[fin - 1]], [ys[fin - 1]])   # Mover la cabeza a x,y final
        cabeza.set_3d_properties([zs[fin - 1]])           # Mover la cabeza a z final
    return linea, cabeza

Esta función se llama una vez por cada cuadro de la animación. FuncAnimation le pasa el número de cuadro (frame) desde 0 hasta 99.

Cálculo del límite de puntos

La variable fin determina cuántos puntos se muestran en el cuadro actual:

$$\text{fin} = \min\!\bigl(\text{len}(xs),\; (\text{frame}+1) \times \text{paso}\bigr)$$

Con paso = 10:

  • Cuadro 0: fin = min(1000, 10) = 10 → muestra los primeros 10 puntos.
  • Cuadro 1: fin = min(1000, 20) = 20 → muestra los primeros 20 puntos.
  • Cuadro 49: fin = min(1000, 500) = 500 → muestra la mitad de la trayectoria.
  • Cuadro 99: fin = min(1000, 1000) = 1000 → muestra toda la trayectoria.

El min(...) protege contra el caso en que (frame+1)*paso supere la longitud del array.

Actualización de la trayectoria acumulada

En Matplotlib, los objetos 3D necesitan dos llamadas separadas para actualizar sus coordenadas:

  • linea.set_data(xs[:fin], ys[:fin]): actualiza las coordenadas x e y del segmento.
  • linea.set_3d_properties(zs[:fin]): actualiza la coordenada z del segmento.

No hay una sola función set_data_3d(x, y, z) en las versiones estándar de Matplotlib; se necesitan estas dos llamadas separadas. Este es un detalle específico de la API 3D de Matplotlib.

Actualización de la cabeza (punto móvil)

La "cabeza" representa la posición actual del punto que "dibuja" la trayectoria. Para moverla al último punto incorporado:

  • xs[fin - 1]: el último punto en x. Se pasa como lista de un elemento [xs[fin-1]] porque Matplotlib espera arrays.
  • La condición if fin > 0 evita acceder a xs[-1] (que en Python indexaría el último elemento del array, no el esperado) cuando el cuadro 0 aún no tiene puntos.

El desarrollo de la animación de principio a fin

  1. Cuadro 0: La trayectoria muestra solo los primeros 10 puntos (cerca del origen). La cabeza está en el punto 10. El atractor apenas empieza a dibujarse.
  2. Cuadros 1–49: La trayectoria crece progresivamente. La cabeza se mueve a lo largo del atractor. Se puede ver cómo la trayectoria empieza a orbitar alrededor de un centro, luego salta al otro, etc.
  3. Cuadros 50–99: La trayectoria casi completa el atractor. En el cuadro 99, se ven todos los 1000 puntos y la cabeza está en el último punto.

📌 ¿Por qué blit=False para gráficos 3D?

blit=True es más eficiente porque no redibuja el fondo: solo actualiza los objetos que cambian. Pero en gráficos 3D de Matplotlib, la perspectiva y los ejes también necesitan actualizarse, lo que causa problemas visuales con blit activado. blit=False es el modo seguro para 3D, aunque más lento.

Resumen de Verificación Numérica

Python · Líneas 339–361
def bloque_9_verificacion(sol, lambda_est, n_cruces):
    pruebas = [
        ("Simulación temporal completa (RK45)", sol.status == 0),
        ("Estabilidad numérica (sin NaN ni Inf)",
            not (np.isnan(sol.y).any() or np.isinf(sol.y).any())),
        (f"Exponente de Lyapunov positivo ({lambda_est:.3f} > 0)", lambda_est > 0),
        (f"Concordancia teórica (ref: 0.906, error: {abs(lambda_est - 0.9056)/0.9056*100:.1f}%)",
            abs(lambda_est - 0.9056) / 0.9056 < 0.10),
        (f"Sección de Poincaré representativa ({n_cruces} cruces)", n_cruces > 20)
    ]
    for nombre, ok in pruebas:
        print(f" {'✅ [SUPERADA]' if ok else '❌ [FALLIDA]'} {nombre}")

Las cinco verificaciones y qué comprueban

#Verificación¿Qué fallaría si no se supera?
1 sol.status == 0: La integración completó el intervalo sin errores. Si el integrador no pudo completar la integración (por ejemplo, si las tolerancias son demasiado estrictas y el paso adaptativo se hace infinitesimalmente pequeño), status sería diferente de 0.
2 not (np.isnan(...).any() or np.isinf(...).any()): Ningún valor de la solución es NaN o infinito. En sistemas muy caóticos, pueden ocurrir desbordamientos numéricos (overflow) que producen valores infinitos o NaN. Esto indicaría que la solución es numéricamente inestable.
3 lambda_est > 0: El exponente de Lyapunov es positivo. Si $\lambda \leq 0$, el sistema no sería caótico con los parámetros estándar, lo que indicaría un error en el cálculo.
4 Error relativo respecto a 0.9056 < 10%. Si el error fuera mayor al 10%, el algoritmo de Benettin no estaría convergiendo adecuadamente con los parámetros usados (n_pasos, tau).
5 n_cruces > 20: La sección de Poincaré tiene suficientes puntos. Si hay muy pocos cruces, la sección de Poincaré no es representativa del atractor. Esto podría ocurrir si la integración fuera muy corta o el plano elegido cortara raramente la trayectoria.
🔬 ¿Por qué automatizar estas verificaciones?

En física computacional, es fundamental tener pruebas que validen que los resultados numéricos son correctos y no son artefactos de la implementación. Estas verificaciones automáticas sirven como "tests de regresión": si alguien modifica el código y algo falla, el programa lo reporta inmediatamente. También sirven para comunicar al lector cuáles son los criterios de éxito del análisis.

La simulación base

Lo primero que hace main() es integrar el sistema desde $(1, 1, 1)$ durante 40 unidades de tiempo con 4000 puntos de salida. Esta simulación base es compartida por los bloques 1, 2 y 8 (evolución temporal, atractor 3D y animación). Los bloques 3, 4, 5, 6 y 7 realizan sus propias integraciones adicionales con distintos parámetros.

La línea t, (x, y, z) = sol.t, sol.y desempaqueta la solución: sol.y es una matriz de forma (3, 4000), y al escribir (x, y, z) = sol.y, Python asigna cada fila a una variable separada.

El patrón if __name__ == "__main__"

Esta construcción es un patrón estándar en Python. Cuando Python carga un archivo, le asigna a la variable especial __name__ el valor "__main__" si ese archivo es el que se ejecutó directamente, o el nombre del módulo si fue importado por otro archivo.

Al envolver main() en esta condición, se logra que:

  • Si se ejecuta python Lorenz_final.py directamente, el análisis completo corre.
  • Si otro script importa este archivo (import Lorenz_final), las funciones quedan disponibles pero el análisis no se ejecuta automáticamente.
