Las Ecuaciones del Movimiento

Fundamento: mecánica Lagrangiana

El péndulo doble no se puede modelar fácilmente con la Segunda Ley de Newton, porque las tensiones internas de los eslabones son incógnitas adicionales. La mecánica Lagrangiana evita este problema trabajando directamente con coordenadas generalizadas.

Los ángulos θ₁ y θ₂ se miden desde la vertical hacia abajo. Las velocidades angulares ω₁ = dθ₁/dt y ω₂ = dθ₂/dt son las otras dos variables de estado.

Las coordenadas cartesianas de cada masa en función de los ángulos son:

$$x_1 = L_1 \sin\theta_1, \quad y_1 = -L_1 \cos\theta_1$$ $$x_2 = L_1\sin\theta_1 + L_2\sin\theta_2, \quad y_2 = -L_1\cos\theta_1 - L_2\cos\theta_2$$

El Lagrangiano del sistema es $\mathcal{L} = T - V$, donde $T$ es la energía cinética y $V$ la potencial. Aplicando las ecuaciones de Euler-Lagrange para $\theta_1$ y $\theta_2$, se obtiene un sistema acoplado de dos ecuaciones de segundo orden, que el código resuelve.

La función derivadas_pendulo(t, estado, ...)

Python · Líneas 48–70
def derivadas_pendulo(t, estado, m1=M1, m2=M2, L1=L1, L2=L2, g=G):
    """
    Sistema acoplado de aceleraciones angulares M(theta) * alpha = b.
    Resuelto analíticamente con la Regla de Cramer (det(M) > 0 siempre).
    """
    th1, w1, th2, w2 = estado
    delta = th1 - th2
    cos_d, sin_d = np.cos(delta), np.sin(delta)

    # Matriz de inercia M
    M11 = (m1 + m2) * (L1 ** 2)
    M12 = m2 * L1 * L2 * cos_d
    M22 = m2 * (L2 ** 2)

    # Fuerzas gravitatorias y centrífugas b
    b1 = -m2 * L1 * L2 * (w2 ** 2) * sin_d - (m1 + m2) * g * L1 * np.sin(th1)
    b2 =  m2 * L1 * L2 * (w1 ** 2) * sin_d - m2 * g * L2 * np.sin(th2)

    det_M = M11 * M22 - (M12 ** 2)
    alpha1 = (b1 * M22 - b2 * M12) / det_M
    alpha2 = (M11 * b2 - M12 * b1) / det_M

    return [w1, alpha1, w2, alpha2]

Esta función implementa las ecuaciones de movimiento del péndulo doble. El estado del sistema tiene cuatro componentes: $[\theta_1, \omega_1, \theta_2, \omega_2]$, y la función devuelve sus derivadas temporales $[\dot\theta_1, \dot\omega_1, \dot\theta_2, \dot\omega_2] = [\omega_1, \alpha_1, \omega_2, \alpha_2]$.

Las relaciones $\dot\theta_i = \omega_i$ son triviales. Lo no trivial es calcular las aceleraciones angulares $\alpha_1$ y $\alpha_2$, que provienen de las ecuaciones de Euler-Lagrange.

La variable delta y por qué aparece

La diferencia $\delta = \theta_1 - \theta_2$ aparece repetidamente en las ecuaciones. El código la calcula una sola vez y reutiliza sus valores trigonométricos cos_d y sin_d. Esto es una optimización: calcular senos y cosenos es computacionalmente más caro que multiplicaciones; al precalcularlos se evita repetirlos.

El sistema matricial y la Regla de Cramer

Las ecuaciones de Euler-Lagrange para el péndulo doble, luego de derivar el Lagrangiano, pueden escribirse en forma matricial como:

$$\underbrace{\begin{pmatrix} M_{11} & M_{12} \\ M_{12} & M_{22} \end{pmatrix}}_{\mathbf{M}(\theta)} \begin{pmatrix} \alpha_1 \\ \alpha_2 \end{pmatrix} = \begin{pmatrix} b_1 \\ b_2 \end{pmatrix}$$

Donde los elementos de la matriz de inercia y el vector de fuerzas son:

$$M_{11} = (m_1 + m_2)L_1^2, \quad M_{12} = m_2 L_1 L_2 \cos(\theta_1-\theta_2), \quad M_{22} = m_2 L_2^2$$ $$b_1 = -m_2 L_1 L_2 \,\dot\theta_2^2\sin\delta - (m_1+m_2)g L_1\sin\theta_1$$ $$b_2 = m_2 L_1 L_2 \,\dot\theta_1^2\sin\delta - m_2 g L_2\sin\theta_2$$

En lugar de llamar a un solver lineal genérico como np.linalg.solve(), el código resuelve este sistema de $2\times 2$ analíticamente mediante la Regla de Cramer:

$$\det(\mathbf{M}) = M_{11}M_{22} - M_{12}^2$$ $$\alpha_1 = \frac{b_1 M_{22} - b_2 M_{12}}{\det(\mathbf{M})}, \qquad \alpha_2 = \frac{M_{11}b_2 - M_{12}b_1}{\det(\mathbf{M})}$$
🔬 ¿Por qué det(M) > 0 siempre?

El determinante es $M_{11}M_{22} - M_{12}^2 = m_2 L_2^2 \left[(m_1+m_2)L_1^2 - m_2 L_1^2 \cos^2\delta\right]$. Como $\cos^2\delta \leq 1$, tenemos $(m_1+m_2) - m_2\cos^2\delta \geq m_1 > 0$. Por lo tanto el determinante nunca es cero y la división siempre está bien definida. Físicamente, $\det(\mathbf{M}) = 0$ solo si las dos barras fueran paralelas y una de las masas fuera cero, lo cual es físicamente imposible con las masas que tiene el sistema.

📌 ¿Por qué usar Cramer y no np.linalg.solve()?

Para un sistema de $2\times 2$, Cramer es equivalente pero más rápido: evita la sobrecarga de llamar a una función general que maneja matrices de cualquier tamaño. Además, da más transparencia matemática: quien lee el código ve explícitamente la fórmula que se está implementando. Para sistemas más grandes (3x3 en adelante), lo correcto sería usar np.linalg.solve().

La función calcular_energia()

Python · Líneas 72–77
def calcular_energia(th1, w1, th2, w2, m1=M1, m2=M2, L1=L1, L2=L2, g=G):
    """Energía mecánica total E = Cinética (T) + Potencial (V)."""
    T = (0.5 * (m1 + m2) * (L1 * w1)**2 + 0.5 * m2 * (L2 * w2)**2 +
         m2 * L1 * L2 * w1 * w2 * np.cos(th1 - th2))
    V = (m1 + m2) * g * L1 * (1.0 - np.cos(th1)) + m2 * g * L2 * (1.0 - np.cos(th2))
    return T + V

Esta función calcula la energía mecánica total del sistema, que debe conservarse ya que no hay fricción ni amortiguamiento. Sirvecomo validador numérico: si la energía se conserva bien, el integrador está funcionando correctamente.

Energía cinética T

La energía cinética tiene tres términos:

$$T = \underbrace{\tfrac{1}{2}(m_1+m_2)L_1^2\,\dot\theta_1^2}_{\text{masa 1 + masa 2 en eslabón 1}} + \underbrace{\tfrac{1}{2}m_2 L_2^2\,\dot\theta_2^2}_{\text{masa 2 en eslabón 2}} + \underbrace{m_2 L_1 L_2\,\dot\theta_1\dot\theta_2\cos(\theta_1-\theta_2)}_{\text{término de acoplamiento}}$$

El tercer término es el acoplamiento: la energía cinética de $m_2$ depende del movimiento de ambos eslabones simultáneamente. Este término es positivo cuando los dos eslabones se mueven en la misma dirección y negativo cuando se mueven en sentido contrario.

Energía potencial V

La energía potencial se toma con el potencial cero en el pivote y midiéndola hacia abajo:

$$V = (m_1+m_2)g L_1(1-\cos\theta_1) + m_2 g L_2(1-\cos\theta_2)$$

El factor $(1 - \cos\theta)$ mide la altura de cada masa respecto a su posición de equilibrio (colgando verticalmente). Cuando $\theta = 0$ (posición de equilibrio), $V = 0$. Cuando $\theta = \pi$ (posición invertida), $V$ alcanza su máximo.

La función simular() con valor por defecto para t_eval

Python · Líneas 79–83
def simular(y0, t_span=(0.0, 40.0), t_eval=None, params=PARAMS_DEF):
    if t_eval is None:
        t_eval = np.linspace(t_span[0], t_span[1], 4000)
    return solve_ivp(derivadas_pendulo, t_span, y0, t_eval=t_eval,
                     args=params, method="RK45", rtol=1e-8, atol=1e-8)

Una diferencia respecto al Lorenz: aquí t_eval tiene valor por defecto None, y si se omite, la función crea automáticamente una grilla de 4000 puntos en el intervalo indicado por t_span. Esto hace a la función más flexible: se puede llamar con o sin especificar los tiempos de salida. Los parámetros de tolerancia (rtol=1e-8, atol=1e-8) son los mismos que en Lorenz por las mismas razones.

El patrón zip(soluciones, CONFIG_PENDULOS)

zip() es una función de Python que toma dos o más iterables y los combina elemento a elemento. Con zip(soluciones, CONFIG_PENDULOS), en cada iteración del for se obtiene simultáneamente un objeto de solución (sol) y el diccionario de configuración del péndulo correspondiente (p). Esto evita tener que indexar manualmente con soluciones[i] y CONFIG_PENDULOS[i].

La línea sol.y[0] extrae la primera fila de la matriz de solución, que corresponde a $\theta_1(t)$. La línea sol.y[2] extrae la tercera fila, que corresponde a $\theta_2(t)$ (recordar: la segunda fila, índice 1, es $\omega_1$).

📌 Acceso al vector de tiempo

t = soluciones[0].t toma el vector de tiempos de la primera solución. Como todos los péndulos se integran en el mismo intervalo con el mismo t_eval, este vector de tiempos es el mismo para todos. Tomarlo del índice 0 es suficiente.

¿Qué se ve en este gráfico?

El panel superior muestra $\theta_1(t)$ para los cuatro péndulos y el inferior $\theta_2(t)$. Los puntos clave a observar son:

  • P1 y P2 (azules): al principio son indistinguibles, luego divergen completamente. Esto es la firma del caos.
  • P3 y P4 (ámbar y rojo): dependiendo de la amplitud inicial, pueden mostrar comportamiento regular (curvas suaves y predecibles) o caótico.
  • Los ángulos no están acotados entre $[-\pi, \pi]$: si un eslabón da una vuelta completa, $\theta$ supera $\pi$ o cae por debajo de $-\pi$ continuamente. Matplotlib lo grafica sin restricciones.

Cómo se pasan los datos a calcular_energia()

La línea th1, w1, th2, w2 = sol.y desempaqueta la matriz de solución: sol.y tiene forma (4, N) (4 variables, N instantes), y al asignarlo a 4 variables Python extrae una fila por variable.

Luego calcular_energia(th1, w1, th2, w2) recibe cuatro arrays de longitud N y devuelve un array E de longitud N, donde cada elemento es la energía total en ese instante.

El error de conservación de energía

Cálculo del error relativo de energía
err_max = np.max(np.abs(E - E[0])) / np.abs(E[0])
  • E - E[0]: diferencia de energía respecto al valor inicial. En un sistema conservativo ideal, esto debería ser cero.
  • np.abs(...): valor absoluto elemento a elemento.
  • np.max(...): el mayor desvío a lo largo de toda la simulación.
  • División por np.abs(E[0]): normalización para obtener el error relativo.

El resultado es el error máximo relativo de conservación de energía a lo largo de toda la simulación de 40 segundos. Con rtol=atol=1e-8, el error típico es del orden de $10^{-6}$ o menor, lo que confirma la precisión del integrador.

🔬 ¿Por qué no es exactamente cero?

El método RK45 introduce un pequeño error en cada paso. Este error se acumula a lo largo de la integración. Un error relativo de $10^{-6}$ significa que después de 40 segundos de simulación, la energía ha variado en una parte en un millón respecto a su valor inicial. Esto es físicamente despreciable y confirma que la integración es confiable. Si el error fuera de orden $10^{-2}$ o mayor, habría que preocuparse.

¿Qué es el espacio de fases del péndulo doble?

El péndulo doble tiene un espacio de fases de dimensión 4: $(\theta_1, \omega_1, \theta_2, \omega_2)$. No podemos visualizarlo directamente. Lo que hace este bloque es proyectar ese espacio 4D sobre dos planos 2D:

  • Fila superior: el plano $(\theta_1, \omega_1)$, llamado espacio de fases del primer eslabón.
  • Fila inferior: el plano $(\theta_2, \omega_2)$, espacio de fases del segundo eslabón.

En cada gráfico se grafica la curva paramétrica: a medida que el tiempo avanza, el punto $(\theta_i(t), \omega_i(t))$ traza una curva. El punto negro es la condición inicial.

La grilla 2×4 de subplots y enumerate()

plt.subplots(2, 4) crea una matriz de 8 ejes, accesibles como axes[fila, columna]. El bucle usa enumerate(zip(...)): enumerate() agrega un contador i que va de 0 a 3, que se usa como índice de columna (axes[0, i] y axes[1, i]).

📌 ¿Qué se espera ver en el espacio de fases?

Para un péndulo simple no caótico, el espacio de fases muestra curvas cerradas elípticas (oscilaciones), o curvas abiertas que atraviesan el plano repetidamente (rotación completa). Para el péndulo doble caótico, el espacio de fases es una nube densa de puntos aparentemente aleatoria: la curva nunca cierra porque la trayectoria nunca se repite exactamente. Esta diferencia visual entre curvas ordenadas y nubes caóticas es una de las formas más intuitivas de identificar caos.

El parámetro bbox_inches="tight" en savefig ajusta el recuadro del archivo PNG para que incluya todos los títulos y etiquetas, aunque excedan los límites nominales de la figura. Es necesario aquí porque plt.suptitle con y=1.00 puede quedar fuera del recuadro por defecto.

Exponente Máximo de Lyapunov (Método de Benettin)

Python · Líneas 159–182 — lyapunov_benettin()
def lyapunov_benettin(y0, params=PARAMS_DEF, d0=1e-6, tau=0.5, n_pasos=70):
    """Algoritmo de Benettin paso a paso para el péndulo doble."""
    s_ref = np.array(y0, dtype=float)
    s_pert = s_ref.copy(); s_pert[0] += d0   # Perturba θ₁

    suma_log, tiempos, hist_lyap = 0.0, [], []

    for k in range(1, n_pasos + 1):
        s_r = solve_ivp(derivadas_pendulo, (0.0, tau), s_ref,
                        args=params, method="RK45", rtol=1e-6, atol=1e-6).y[:, -1]
        s_p = solve_ivp(derivadas_pendulo, (0.0, tau), s_pert,
                        args=params, method="RK45", rtol=1e-6, atol=1e-6).y[:, -1]

        delta = s_p - s_r
        d1 = np.linalg.norm(delta)
        suma_log += np.log(d1 / d0)

        t_act = k * tau
        tiempos.append(t_act)
        hist_lyap.append(suma_log / t_act)

        # Renormalización en el espacio de 4 dimensiones
        s_ref = s_r
        s_pert = s_r + d0 * (delta / d1)

    return np.array(tiempos), np.array(hist_lyap)

Diferencias con el Lyapunov del Lorenz

La lógica del algoritmo de Benettin es idéntica al Bloque 4 del script de Lorenz, pero hay diferencias importantes de parametrización:

ParámetroLorenzPéndulo dobleRazón
Espacio de estado $\mathbb{R}^3$ $\mathbb{R}^4$ El péndulo doble tiene 4 variables de estado.
$d_0$ $10^{-8}$ $10^{-6}$ En el péndulo se usa una perturbación mayor porque las escalas de movimiento (ángulos en rad) son más grandes que las del Lorenz.
$\tau$ 0.1 0.5 Pasos más largos son suficientes porque el péndulo doble es más lento que el Lorenz (los tiempos caóticos son de varios segundos).

📌 La norma en 4D

d1 = np.linalg.norm(delta) calcula la norma euclídea en el espacio de 4 dimensiones: $d_1 = \sqrt{(\Delta\theta_1)^2 + (\Delta\omega_1)^2 + (\Delta\theta_2)^2 + (\Delta\omega_2)^2}$. Esta norma mezcla ángulos (en rad) con velocidades angulares (en rad/s), que tienen unidades diferentes. Es una elección pragmática: lo que importa no es la escala absoluta sino la tasa de crecimiento relativa $\ln(d_1/d_0)$, que captura la divergencia exponencial.

¿Qué significa $\lambda > 0$ para el péndulo doble?

Un exponente positivo confirma que el sistema es caótico para esas condiciones iniciales. Los valores típicos para el péndulo doble con estos parámetros son $\lambda \approx 1$–$5\,\text{s}^{-1}$, dependiendo de la energía inicial. A mayor energía (ángulos más grandes), mayor la tasa de divergencia y mayor el exponente.

Un $\lambda$ cercano a cero o negativo indica que para esa condición inicial, el sistema es regular (oscilatorio periódico). Esto ocurre con amplitudes pequeñas donde el péndulo doble se comporta aproximadamente como un sistema lineal.

El doble barrido 2D

Este es el bloque más computacionalmente costoso del programa. Realiza un barrido sobre una grilla de $30 \times 30 = 900$ condiciones iniciales, calculando el exponente de Lyapunov para cada una. El estado inicial siempre tiene $\theta_2 = 0$ y $\omega_2 = 0$, variando solo $\theta_1 \in [-\pi, \pi]$ y $\omega_1 \in [-4, 4]$ rad/s.

Para cada par $(\theta_1, \omega_1)$:

  • Se llama a lyapunov_benettin() con solo 30 pasos (en lugar de 70). Es una estimación rápida, no de máxima precisión.
  • El resultado final hist[-1] (el último valor del exponente acumulado) se guarda en la celda correspondiente de la matriz mapa[i, j].
  • Nótese que i indexa filas (eje y = $\omega_1$) y j indexa columnas (eje x = $\theta_1$).
⚠️ Costo computacional del doble bucle

900 llamadas a lyapunov_benettin(), cada una con 30 integraciones de RK45 (60 en total, una para referencia y una para perturbado), implica $900 \times 60 = 54\,000$ integraciones de EDOs. Es por eso que res=30 es un valor de compromiso: una grilla de $100\times 100$ daría un mapa 11 veces más detallado pero tomaría aproximadamente 11 veces más tiempo.

🌪️ Interpretación del mapa de calor

El mapa revela la estructura del espacio de condiciones iniciales del péndulo doble. Las regiones regulares forman "islas" de color oscuro rodeadas por zonas caóticas brillantes. Las islas corresponden a trayectorias confinadas en toros del espacio de fases (modos cuasiperiódicos). Esta estructura se llama estructura KAM (Kolmogorov-Arnold-Moser): a bajas energías domina el orden, y al aumentar la energía las islas se fragmentan y el caos invade el espacio de fases.

Modos normales del péndulo doble linealizado

Para oscilaciones pequeñas ($\theta_1, \theta_2 \ll 1$), el péndulo doble se puede linealizar. El sistema linealizado tiene dos frecuencias naturales (modos normales):

$$\omega_1 = \sqrt{\frac{g}{L_1}(2 - \sqrt{2})} \approx 2.394\,\text{rad/s}$$ $$\omega_2 = \sqrt{\frac{g}{L_1}(2 + \sqrt{2})} \approx 5.780\,\text{rad/s}$$

Estas son soluciones exactas para el caso simétrico $m_1 = m_2$, $L_1 = L_2$. Cada modo corresponde a un patrón de oscilación coherente:

  • Modo 1 (frecuencia baja $\omega_1$): los dos eslabones oscilan en fase (se mueven juntos en la misma dirección). La condición inicial correspondiente es $\theta_2 = \sqrt{2}\,\theta_1$.
  • Modo 2 (frecuencia alta $\omega_2$): los dos eslabones oscilan en contrafase (se mueven en direcciones opuestas). La condición inicial es $\theta_2 = -\sqrt{2}\,\theta_1$.

El código simula con la condición inicial del modo 1 con amplitud pequeña ([0.05, 0.0, 0.05*√2, 0.0]) para verificar que la frecuencia numérica coincide con la analítica.

Detección numérica de la frecuencia: cruces por cero ascendentes

Detección de cruces por cero de θ₁
cruce_t = sol_modo1.t[1:][(sol_modo1.y[0, :-1] < 0) & (sol_modo1.y[0, 1:] >= 0)]

Esta línea detecta los instantes en que $\theta_1(t)$ cruza el cero de negativo a positivo (cruces ascendentes). El período de oscilación es el intervalo entre cruces sucesivos:

  • sol_modo1.y[0, :-1]: valores de $\theta_1$ en todos los instantes excepto el último.
  • sol_modo1.y[0, 1:]: valores de $\theta_1$ en todos los instantes excepto el primero.
  • La condición booleana detecta pares consecutivos donde $\theta_1$ pasa de negativo a positivo.
  • sol_modo1.t[1:][...]: selecciona los tiempos correspondientes a esos cruces.

Luego np.diff(cruce_t) calcula las diferencias entre cruces sucesivos (cada diferencia es un período completo de oscilación). El período promedio se multiplica por 2 porque un cruce ascendente ocurre una vez por período completo:

$$T_1^{\text{num}} = 2 \cdot \overline{\Delta t_{\text{cruces}}}, \qquad \omega_1^{\text{num}} = \frac{2\pi}{T_1^{\text{num}}}$$
📌 ¿Por qué se multiplica por 2?

Un cruce ascendente por cero ocurre cuando la oscilación pasa de su semiciclo negativo al positivo. Esto ocurre exactamente una vez por período completo. El intervalo entre dos cruces ascendentes consecutivos es un período completo $T$. Por lo tanto $T_1^{\text{num}} = \overline{\Delta t_{\text{cruces}}}$. La multiplicación por 2 en el código: T1_num = 2.0 * np.mean(np.diff(cruce_t)) sugiere que los cruces detectados son cada semiperíodo (tanto ascendentes como descendentes), pero mirando la condición, solo se detectan ascendentes. Esto puede ser una inconsistencia menor en el código: si solo hay cruces ascendentes, el factor 2 sobreestima el período a la mitad. Este es uno de los casos donde la interpretación no puede determinarse con certeza sin correr el código y verificar el valor de cruce_t.

datos = {}
def recalcular():
    sA = simular([np.pi/2, 0.0, np.pi/2, 0.0], t_span=(0.0, T_MAX), t_eval=t_eval)
    sB = simular([np.pi/2 + 1e-4, 0.0, np.pi/2, 0.0], t_span=(0.0, T_MAX), t_eval=t_eval)
    th1A, th2A = sA.y[0], sA.y[2]
    th1B, th2B = sB.y[0], sB.y[2]
    datos["x1A"] = L1 * np.sin(th1A); datos["y1A"] = -L1 * np.cos(th1A)
    datos["x2A"] = datos["x1A"] + L2 * np.sin(th2A)
    datos["y2A"] = datos["y1A"] - L2 * np.cos(th2A)
    # ... (similar para B) ...
    datos["th1A"], datos["th2A"] = th1A, th2A
    datos["th1B"], datos["th2B"] = th1B, th2B
recalcular()

recalcular() realiza dos cosas fundamentales:

  1. Integra las EDOs para los dos péndulos (A = referencia, B = perturbado con $\Delta\theta_1 = 10^{-4}$ rad) durante 15 segundos.
  2. Convierte ángulos a coordenadas cartesianas: las ecuaciones de posición son directas:
    $$x_1 = L_1\sin\theta_1, \quad y_1 = -L_1\cos\theta_1$$ $$x_2 = x_1 + L_2\sin\theta_2, \quad y_2 = y_1 - L_2\cos\theta_2$$

El signo negativo en $y_1 = -L_1\cos\theta_1$ refleja que el eje y de Matplotlib apunta hacia arriba, pero el péndulo cuelga hacia abajo. Con $\theta = 0$ (posición vertical), $y_1 = -L_1 = -1$ m (por debajo del pivote), que es correcto.

Todo se guarda en el diccionario datos, que actúa como memoria compartida entre recalcular() y actualizar(). Esta es una forma de compartir datos entre funciones anidadas sin usar variables globales explícitas.

La list comprehension de simulación

La línea soluciones = [simular(p["y0"]) for p in CONFIG_PENDULOS] es una list comprehension: una forma compacta de construir una lista aplicando una función a cada elemento de otra lista. Es equivalente a:

Equivalente explícito (más verboso)
soluciones = []
for p in CONFIG_PENDULOS:
    soluciones.append(simular(p["y0"]))

El resultado es una lista de cuatro objetos de solución, uno por cada configuración de péndulo. Estos cuatro objetos se pasan a los bloques 1, 2, 3 y 6.
